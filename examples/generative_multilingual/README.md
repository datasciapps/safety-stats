# Generative example: multilingual jailbreak rewrites

Every other example in this repository conditions on a **fixed set of prompts**. This one
does not have any. See [generative evaluation](../../docs/generative-evaluation.md) for the
feature itself; this is a worked demonstration of it. The evaluator declares a structural taxonomy with target weights and a
frozen stochastic rewrite kernel; the prompts are generated by sampling that design, so
path selection and rewrite generation are part of the uncertainty the interval reports.

The design here compiles to **264 terminal structural paths**, of which a 1,200-draw
evaluation touches a few hundred. The point is that you never enumerate them.

## What is real and what is simulated

The rewrite kernel is `DeterministicFakeKernel` and the target model is
[`simulated_target.py`](simulated_target.py). **No model is called and nothing is
evaluated.** That is deliberate, and it is what makes the example worth reading: because
the true failure probability of every structural path is declared in that file, the true
root risk is computable in closed form, and the interval the package reports can be
checked against it rather than merely inspected.

Everything else is the real code path — taxonomy compilation, counter-based selection,
rewrite execution with retry and deduplication, Inspect dataset materialization, the
outcome join, and inference. Swapping in a real evaluation replaces one function; see
[Using a real model](#using-a-real-model).

## The design

| level | source | values |
|---|---|---|
| `problem_class` | seed manifest | chemical synthesis (0.6), biological agents (0.4) |
| `semantic_seed_id` | seed manifest | 8 fixed seeds, equal within class |
| `language` | inline arm | english 0.4, french 0.2, german 0.2, maltese 0.2 |
| `style` | inline arm | plain 0.5, conversational 0.3, formal 0.2 |
| `wrapper` | `wrapper-arms.csv` | direct_request 0.5, roleplay 0.3, nested_task 0.2 |

Two authoring features earn their place rather than being decoration:

- a **constraint** removes `nested_task` under Maltese, because the wrapper depends on
  instruction-following the rewriter cannot hold in a low-resource language. Those paths
  are outside the declared design, not merely rare. The surviving wrappers renormalize to
  0.625 / 0.375.
- **context weights** give English a different style mix (0.4 / 0.3 / 0.3), since it is
  the highest-resource language here.

The declared truth concentrates risk where the structure predicts: Maltese carries 20% of
the target weight at roughly 7% risk, against 2% for English. True root risk is **0.03504**.

## Running it

Compile the taxonomy and see what it contains:

```bash
python examples/generative_multilingual/compile_tree.py
```

Run one complete evaluation, plan to interval:

```bash
python examples/generative_multilingual/run_evaluation.py
```

```
design          : direct, 1200 rewrites
rewrites        : 1200 accepted, 0 duplicates rejected, 0 exhausted

root
  true risk           0.03504
  point estimate      0.03250
  95% upper bound     0.04224
  covers the truth    True
  method              clopper_pearson_one_sided_missingness_robust
  failures / draws    39 / 1200

nodes reported 390, unsampled 13
```

Measure whether the intervals actually cover, over many evaluations:

```bash
python examples/generative_multilingual/validate_coverage.py --replicates 400
```

```
root
  empirical coverage   0.960   (nominal >= 0.95)
  mean point estimate  0.03491   (truth 0.03504)
  mean upper bound     0.04491
  bound slack          0.00987
```

Each replicate redraws the sample as well as the outcomes, so what is measured is the whole
procedure, not the noise in one fixed sample. Coverage lands just above nominal rather than
far above it, and the mean point estimate sits on the truth.

## Four things the example is built to show

### A single interval may miss, and that is the guarantee working

`run_evaluation.py` reports four language slices pointwise at α = 0.05. About one run in
five, one of them sits below the truth and prints `False`. That is not a defect: a 95%
bound is wrong 5% of the time by construction, and four of them miss at least once about
19% of the time. `validate_coverage.py` is the honest check, and it reports 0.958–0.988
across the four slices.

### Some questions are not subtrees

"What is the risk in Maltese?" cannot be answered by a hierarchy node. Semantic seeds are a
mandatory stratification frontier, so `language` sits *below* them and English is 32
separate nodes rather than one. Reading a per-language number off the tree means taking a
worst case across those 32 nodes, which at ~30 draws each gives bounds around 0.13–0.36 —
useless.

The estimand is still perfectly well defined: a declared-weight mean over the matching
terminal paths. The draws landing in it are still independent conditional on their count,
so the same exact construction applies. `estimate_slice` does exactly that, and the same
question answered properly gives 0.027–0.112. **This estimator exists because building this
example exposed the gap.**

### Pairing is where the comparison gets its power

Both cohorts evaluate the **same** accepted rewrites, so each sampling unit yields a paired
difference in {-1, 0, +1}. The dependence between arms lives inside a unit, where it is
unrestricted; independence is only claimed across units, which is exactly what path
selection and rewrite generation deliver.

```
candidate versus baseline on the same rewrites
  true risk difference   +0.01226
  point estimate         +0.01583
  95% upper bound        +0.02826   covers: True
  method                 paired_binomial_cells
  discordant units       24 candidate-only, 5 baseline-only, 1171 concordant
  ignoring the pairing   +0.03883   (1.37x wider)
```

1,171 of 1,200 units are concordant and contribute **exactly zero**, so the bound reads
only the 29 units where the models disagreed. How much that is worth depends entirely on
how alike the arms are; `research/generative_paired_comparison.py` measures it:

| how alike the arms are | pairing gain |
|---|---:|
| identical response to prompt difficulty | 2.0x – 9.8x |
| half coupled (the case shown above) | 1.24x – 1.44x |
| independent given the prompt | 1.02x |

Pairing never *widens* the bound. That is the opposite of what
[slice 0](../../docs/generative-design-decisions.md) found for importance
sampling, and for a concrete reason: importance sampling buys variance by making the
coefficients unequal, which a bounded-weight bound charges for, whereas pairing shrinks the
*range* of each unit's contribution, which is what such a bound is most sensitive to.

### The stratum floor has a price, and it is not rounding

`plan-stratified.yaml` sets `minimum_rewrites_per_stratum: 40` so no seed can be missed.
Holding the outcomes fixed and varying only the design:

| design | draws per stratum | coefficient ratio | kernel | root bound |
|---|---|---:|---|---:|
| direct | — | 1.000 | exact | 0.00249 |
| stratified, no floor | 144 / 160 | 1.000 | exact | 0.00249 |
| stratified, floor 40 | 145–157 | 1.033 | weighted | 0.00254 |

Proportional allocation here is **exactly free** — the weights divide 1,200, so the
coefficients stay equal and the sharp Clopper–Pearson kernel is retained. The entire 2.0%
penalty comes from the floor pushing allocation away from proportional. That is a
deliberate purchase: 2% of bound width for a guarantee that no seed goes unsampled.

## Using a real model

The scripts above are for reading; the CLI is for running. The workflow is two phases with
an Inspect run between them, because the prompts have to exist before anything can evaluate
them.

Inspect the design without generating anything:

```bash
inspect-safety-stats generative compile --plan examples/generative_multilingual/plan-direct.yaml
```

Generate the prompts and write everything an Inspect run needs:

```bash
inspect-safety-stats generative materialize --plan examples/generative_multilingual/plan-direct.yaml --output run/generative --kernel mypackage.rewriters:build_kernel
```

`--kernel` takes `fake` (the deterministic offline kernel used above), `fake:invalid_every=N`
to exercise the retry path, or `module:attribute` naming your own object implementing the
`RewriteKernel` protocol — a kernel or a zero-argument factory. Nothing in this package
depends on a particular rewriter client.

That writes `datasets/dataset.jsonl` for Inspect, `selections.csv` and `rewrites.csv` as the
ledgers, and `prompts.restricted.csv` as the only artifact containing prompt text.

The ledgers are appended as each rewrite completes, so a run killed by a rate limit or a
dropped connection leaves a usable record. Add `--resume` to continue it; only the outstanding
units run again. Units whose retries were exhausted are **not** retried, since they are part of
the accepted distribution the estimand is defined against, but units that errored are.

Evaluate the dataset with Inspect and your judge, then:

```bash
inspect-safety-stats generative analyze --plan examples/generative_multilingual/plan-direct.yaml --artifacts run/generative --logs run/logs --output run/report --slice language=maltese --compare candidate:baseline
```

Cohorts are matched to logs by the model each declares in `target.cohorts`, so the plan's
`simulated/baseline` must become the model identifier you actually ran.

**The plan is re-compiled during analysis and checked against the selection ledger.** A plan
edited between the two phases is rejected rather than silently changing the estimand — the
ledger records what was evaluated, and the plan has to still reproduce it.

The report directory carries `report.html`, `report.json`, `nodes.csv`, `taxonomy.csv`,
`comparisons.csv`, `diagnostics.csv`, `acceptance.csv` and `checksums.json`, which holds the
SHA-256 of each of the others. `report.html` is a self-contained page -- it
embeds its own data and fetches nothing -- showing the root bound, the design, comparisons,
slices, a collapsible hierarchy with unsampled nodes marked, and provenance. Both it and
`report.json` name the taxonomy and kernel fingerprints they were produced under, so two
runs cannot be pooled by accident, and state the estimand in words.

## Limitations

- **Slices and comparisons are pointwise.** Both overlap the tree's nodes, so neither can
  join its Šidák frontiers, and neither is part of a simultaneous family. Comparing several
  nodes means spending alpha across them yourself.
- **Risk difference only.** Ratios and relative reductions are not implemented; the two arm
  intervals are reported alongside each comparison, so they can be derived by hand under a
  union bound.
- **The judge is not modelled here.** Neither plan declares a judge calibration, so nothing
  here corrects for a fallible scorer. A generative plan can declare one: see
  [Judge misclassification](../../docs/judge-misclassification.md#on-the-generative-path).
